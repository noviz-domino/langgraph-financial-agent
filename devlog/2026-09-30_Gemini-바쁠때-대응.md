## TL;DR

1. Gemini 무료 등급은 사용자가 몰리면 **503(과부하)을 주거나 답이 늦다.** 그런데 화면에는 "요청을 이해하지 못했어요"가 나왔다 — 사용자 잘못이 아닌데 다시 말하라고 한 셈.
2. SDK 기본값이 **6번까지 다시 보내서** 바쁠 때 1분 넘게 "…"로 멈춰 있을 수 있었다.
3. **20초 제한 + 총 2번 시도**로 줄이고, 서버 쪽 실패는 "지금 AI 서버가 바빠요. 잠시 후 같은 말을 다시 보내 주세요."로 따로 안내한다 (B26).

---

## 정한 것

| 정한 것 | 결정 | 이유 |
|---|---|---|
| 재시도를 어디서 | SDK 설정(`max_retries=2`, `timeout=20`) | SDK가 이미 503·429에 기다렸다 다시 보내는 기능이 있다. 직접 반복문을 만들 필요가 없다 |
| 몇 번 | 처음 1번 + 재시도 1번 | 잠깐 몰린 경우는 한 번이면 대부분 풀린다. 더 기다리게 하기보다 빨리 알려 준다 (최대 약 40초) |
| 실패 구분 | `is_retryable`이 참이거나 시간 초과면 `llm_busy`, 그 밖은 `not_understood` | "다시 보내면 될 수 있는 오류"를 LangChain이 이미 표시해 둔다. 오류 문구로 가르지 않는다 |
| 승인 화면의 수정 요청 중 실패 | 그대로 둠 (승인 대기 요청 유지, '예/취소' 안내) | 요청을 잃지 않는 게 먼저. 문구 구분은 필요해지면 |

- `max_retries`는 이름과 달리 **총 시도 횟수**다 (SDK 설명: 재시도를 끄려면 0이 아니라 1)

## 확인

- Gemini 호출 없이 가짜 오류 5종으로 확인: 503·429·시간 초과 → "바빠요", 400·형식 오류 → "이해하지 못했어요"
- 서버에 다시 배포: 서비스 `active`, 시작 로그에 오류 없음

## 호출 제한 강화

무료 등급 한도 안에서 여러 방문자가 나눠 쓰도록 제한을 줄였다.

| | 전 | 후 |
|---|---|---|
| 방문자마다 | 10분에 30번 | **1분에 3번 + 10분에 10번** (둘 중 하나라도 넘으면 429) |
| 서버 전체 | 하루 500번 | **하루 50번** |
| 한 번에 보내는 글자 | 300자 | 그대로 |

- 1분 제한은 연달아 누르는 것을, 10분 제한은 오래 붙잡고 쓰는 것을 막는다. 요청 시각 목록 하나로 두 구간을 함께 센다
- 가짜 시계로 확인: 1분 안 4번째 막힘·1분 뒤 다시 됨, 50초 간격 11번째 막힘, 하루 51번째 막힘
- 하루 횟수는 메모리에만 있어서 **서버를 재시작하면 0부터 다시 센다** (알고 둔다)

## 배운 것

- 공개하고 나서야 보이는 실패가 있다. 혼자 쓸 때는 503을 거의 못 봤다.
- 라이브러리 기본값을 확인하자. "알아서 재시도"가 친절해 보여도 사용자는 그동안 멈춘 화면을 본다.
