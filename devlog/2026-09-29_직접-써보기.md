## TL;DR

1. 직접 써 보니 **화면에 Google SDK 경고가 섞여 나오고**, "안녕"에 "죄송해요, 도와드릴 수 없어요"만 나와서 딱딱했다 → 경고를 숨기고, 처리 불가 안내에 예시 문장을 붙였다.
2. **"카드" 한 단어에 카드 잠금이 진행됐다.** 되묻는 질문이 "카드를 알려 주세요"뿐이라 잠금 중인 줄 몰랐다 → 질문에 업무 이름을 붙였다 ("카드 일시 잠금을 하려면 …").
3. 시나리오 확인에서 **출금 계좌를 말하지 않았는데 LLM이 생활비로 채웠다** → 출금 계좌만은 짐작을 허용하지 않기로 했다 (B25).

## 써 본 결과

| 입력 | 결과 | 판단 |
|---|---|---|
| "안녕" | 처리 불가 안내 + SDK 경고 | 고침 — 경고 숨김, 예시 문장 |
| "어" (승인 화면) | 다시 물음 | 의도대로 — "어?"(되묻는 말)와 구분이 안 돼서 승인으로 치지 않는다 |
| "비상금 잔액 100만원으로 바꿔줘" | 처리 불가 | 의도대로 — 잔액을 직접 바꾸는 기능은 없어야 한다 |
| "내 카드 알려줘" | 처리 불가 | 의도대로 — 카드 목록 조회는 2차 범위 |
| "카드" → "생활비카드" | 잠금 승인 화면까지 감 | 고침 — 되묻는 질문에 업무 이름 |

## 결정

| # | 결정 | 이유 |
|---|---|---|
| 1 | 되묻는 질문에 업무 이름 | 짧은 말에 업무를 짐작했을 때 무엇이 진행 중인지 보이게 |
| 2 | 출금 계좌는 짐작 금지 (말함·이어받음·보여준 후보만) | 돈이 나가는 칸. 코드는 "뜻으로 알아들음"과 "지어냄"을 구분할 수 없다 |
| 3 | "보여준 후보에서 순서로 고른 것"은 짐작이 아님 | 막으면 "두 번째 거"에 끝없이 되묻게 된다 |

## 배운 것

- **테스트가 다 통과해도 직접 써 봐야 보이는 게 있다.** 시나리오는 "기대한 동작"을 확인하지만, 경고 메시지나 딱딱한 말투, "무슨 업무 중인지 모르겠다"는 느낌은 써 봐야 안다.
- 시나리오 확인이 시작할 때 장부를 되돌리지 않아서, 직접 써 본 이체가 결과에 섞였다. 반대로 확인이 끝나면 직접 써 본 변경이 지워진다 — 파일 설명에 경고를 적었다.
- 확인: `scenarios.py` 49/49 (Gemini 41회 + 가짜 LLM)

## 웹 화면 (`feat/web` 브랜치)

포트폴리오로 보여줄 수 있게 웹 화면을 붙였다. `main`(과제 제출본)은 건드리지 않으려고 브랜치를 나눴다.

| 정한 것 | 결정 | 이유 |
|---|---|---|
| 구조 | FastAPI 서버가 기존 그래프를 그대로 부름 | 에이전트 코드는 두고 입구만 바꾼다 (`main.py`와 같은 역할) |
| 화면 기술 | HTML + JavaScript 한 장 | 채팅창 하나라 빌드 도구가 필요 없다. 배포도 쉽다 |
| 레이아웃 | 데스크톱 2단(왼쪽 장부, 오른쪽 채팅), 폰은 채팅만 | 포트폴리오는 PC로 짧게 본다 — "말했더니 → 승인 버튼 → 옆 잔액이 바뀜"이 한 화면에 |
| 방문자마다 장부 | `data_store.use_ledger` (ContextVar) | 장부 파일이 하나면 공개하는 순간 모든 방문자가 같은 계좌를 쓴다 |
| 비용 보호 | 세션마다 10분 30번, 하루 500번, 300자 | 공개된 채팅창은 누구나 계속 보낼 수 있다 |

- LangGraph가 노드를 다른 스레드에서 돌리면 "누구의 장부인가"가 전달되지 않을까 걱정했는데, 가짜 LLM으로 두 방문자를 돌려 보니 장부가 따로 움직였다
- Windows 앱 제어 정책이 `.venv`의 `uvicorn.exe`를 막아서 `python -m uvicorn`으로 실행한다
- 브라우저로 확인: 이체 → 승인 버튼 → 잔액 색 변화·처리 기록, 카드 잠금 되묻기 → 후보 버튼, 폰 화면·밝은 모드
- 가짜 LLM으로 API 확인: 방문자 분리, 처음으로, 잘못된 세션(422)·모르는 세션(404)·긴 입력(422)·31번째 요청(429)
